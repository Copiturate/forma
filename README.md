# FORMA — архитектура пространства

Приложение вымышленного архитектурного бюро: посетитель рассчитывает стоимость работ и отправляет бриф, а команда обрабатывает заявки в защищённом кабинете. Проект развивает исходный авторский лендинг: сохранены русскоязычная подача, спокойная типографика и архитектурные композиции, нарисованные CSS.

**Java 21 · Spring Boot 3.5.16 · Spring Security · Spring Data JPA · H2 · Flyway · Vanilla JavaScript**

![Главная страница FORMA](docs/screenshots/overview.png)

## Возможности

- Адаптивный сайт с мобильным меню, клавиатурной навигацией и поддержкой reduced motion.
- Серверный расчёт диапазона стоимости трёх направлений для площади 20–2000 м². Денежные значения — целые рубли.
- Бриф с валидацией, явным согласием на сохранение и квитанцией с номером заявки.
- Повтор одинакового запроса с тем же UUID возвращает прежнюю квитанцию. Повтор UUID с другими данными отклоняется с `409`.
- Файловая база сохраняет заявки после перезапуска; Flyway управляет схемой, Hibernate проверяет её.
- Кабинет бюро: вход, фильтрация по статусу, страницы по 12 заявок и управляемый жизненный цикл.
- Оптимистическая блокировка предотвращает потерю изменений, когда одну заявку обрабатывают два сотрудника.
- CSRF, сессионная авторизация, BCrypt, CSP без сторонних ресурсов, ограничение размера JSON и частоты запросов.
- Unit/integration-тесты и воспроизводимая браузерная проверка полного сценария. GitHub Actions выполняет оба набора.

**Это учебное бюро.** Тарифы демонстрационные, сервис не отправляет письма и не обещает обратный звонок. Введите вымышленные контакты. Приложение действительно сохраняет брифы в базе.

## Быстрый запуск

Нужен **JDK 21**. Maven устанавливать не нужно: в репозитории есть Maven Wrapper 3.9.11 с проверкой SHA-256. Для первой сборки нужен доступ к Maven Central. Проверьте `java -version` и `JAVA_HOME`: Java 8 для этого проекта не подходит. Настройка JDK — по [официальной инструкции Temurin](https://adoptium.net/installation/).

Windows PowerShell, из корня проекта:

```powershell
# Выберите собственный пароль (12 и более символов, не более 72 байт UTF-8).
$env:FORMA_ADMIN_USERNAME = 'studio'
$env:FORMA_ADMIN_PASSWORD = 'replace-with-your-own-password'
.\mvnw.cmd clean verify
java -jar target/forma-1.0.0.jar
```

macOS / Linux:

```bash
export FORMA_ADMIN_USERNAME=studio
export FORMA_ADMIN_PASSWORD='replace-with-your-own-password'
bash mvnw clean verify
java -jar target/forma-1.0.0.jar
```

Откройте [сайт](http://localhost:8080) и [кабинет](http://localhost:8080/studio.html). Логин — `FORMA_ADMIN_USERNAME`, пароль — заданный вами. Если пароль не задан, сайт и форма работают, но учётная запись кабинета **не создаётся**. Слишком короткий заданный пароль останавливает запуск с понятной ошибкой.

Для разработки: `./mvnw spring-boot:run` (Windows: `.\mvnw.cmd spring-boot:run`). Frontend и API обслуживает один сервер; Node.js и отдельная сборка интерфейса для запуска приложения не нужны. Не открывайте HTML через `file://`: форма обращается к Java API.

### Конфигурация

Список переменных — в [.env.example](.env.example). Spring Boot **не читает `.env` автоматически**: экспортируйте переменные в shell или задайте их в IDE. Docker Compose читает `.env` сам.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | HTTP-порт |
| `FORMA_ADMIN_USERNAME` | `studio` | Логин кабинета |
| `FORMA_ADMIN_PASSWORD` | пусто | Включает учётную запись кабинета |
| `FORMA_DB_URL` | `jdbc:h2:file:./data/forma;DB_CLOSE_ON_EXIT=FALSE;WRITE_DELAY=0` | Файловая H2; синхронная фиксация, путь относительно каталога запуска |
| `FORMA_DB_USERNAME` | `sa` | Пользователь базы |
| `FORMA_DB_PASSWORD` | пусто | Пароль базы для локального демо |
| `FORMA_COOKIE_SECURE` | `false` | `true` при публикации через HTTPS |

Файлы базы находятся в `data/` и исключены из Git. Запускайте JAR из одного и того же рабочего каталога. Для резервной копии остановите приложение и скопируйте `data/`. Не запускайте два экземпляра с одним файлом базы. Смена пароля базы в переменных не меняет пароль уже созданной H2.

### Docker

```bash
docker compose up --build
```

Предварительно задайте `FORMA_ADMIN_PASSWORD` в окружении или в локальном `.env`. Compose публикует порт только на `127.0.0.1`, данные хранит в именованном volume `forma-data`. Контейнер запускается от непривилегированного пользователя; Java-тесты выполняются при сборке образа. `docker compose down` сохраняет данные. В текущей среде Docker не установлен, этот путь подготовлен, но не запускался.

## Проверки

```powershell
.\mvnw.cmd clean verify
```

JUnit + Spring Boot Test + MockMvc проверяют формулы и границы расчёта, валидацию и согласие, доступ и CSRF, миграции/JPA, повторные и конкурентные запросы, фильтрацию/пагинацию, переходы статусов и конфликты версий, ограничения тела, вход и HTTP-ошибки. Тесты используют изолированную H2 в памяти и не трогают пользовательскую базу.

Дополнительный браузерный сценарий требует Node.js 22+:

```bash
npm ci
npx playwright install chromium
```

Запустите JAR с **одноразовой базой** и тестовым паролем, затем в другом терминале запустите тест с тем же паролем:

```powershell
# Терминал 1
$env:FORMA_ADMIN_PASSWORD = 'browser-test-password-only'
$env:FORMA_DB_URL = 'jdbc:h2:mem:browser;DB_CLOSE_DELAY=-1'
java -jar target/forma-1.0.0.jar

# Терминал 2
$env:FORMA_ADMIN_PASSWORD = 'browser-test-password-only'
npm run test:e2e
```

Для Linux/macOS задайте переменные через `export`. Браузерный тест создаёт и закрывает заявку, проверяет расчёт, перенос параметров в бриф, мобильное меню, ширины 360/390/768/1024/1440 px, вход/выход, безопасное отображение HTML как текста, фильтрацию и весь цикл статусов. Сохраняет скриншоты в `docs/screenshots/`. Для другого порта задайте `FORMA_TEST_URL`. Подробные фактические результаты — в [отчёте проверки](docs/VERIFICATION.md).

Проверка файлового хранения: `npm run test:persistence`. Скрипт сам запускает JAR на порту 18081 с временной файловой базой, сохраняет заявку, перезапускает приложение и проверяет данные после входа. Нужен JDK 21 в `JAVA_HOME` или `PATH`; предварительно соберите JAR. Пользовательская база не затрагивается.

## Границы реализации

Один экземпляр приложения и один кабинет без регистрации пользователей — осознанный масштаб портфолио. H2 подходит для локального демо и небольшого стенда, не для масштабируемой CRM. Нет отправки email, вложений, оплаты и автоматического удаления заявок. Ограничитель частоты работает в памяти одного процесса и видит адрес соединения, не доверяя `X-Forwarded-For`.

Перед публичным запуском нужны HTTPS, собственные правила обработки данных и срок хранения, резервные копии, секреты вне Git и лимиты на reverse proxy. При росте сервиса следующий обоснованный шаг — PostgreSQL, многопользовательский доступ, журнал действий и распределённые лимиты. Это будущие расширения, а не скрытые зависимости текущего запуска.

Шрифты Cormorant Garamond и Manrope включены с лицензиями SIL Open Font License в `static/fonts/`. Лицензия на остальной проект намеренно не назначена: её выбирает автор перед публикацией.
