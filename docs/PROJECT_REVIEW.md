# Аудит и итог доработки

## Исходное состояние

В папке были только `index.html` и `styles.css`. Это демонстрационный русскоязычный лендинг архитектурного бюро FORMA с пятью разделами и CSS-иллюстрациями. Java, backend, базы, тестов, документации и Git-репозитория не было.

Полезные части сохранены: структура разделов, тексты философии и подхода, сетки, адаптивные правила, архитектурные CSS-композиции, типографическое направление и reduced-motion.

## Исправлено

| Было | Стало |
|---|---|
| Подключён отсутствующий `script.js` | Реальные ES-модули для меню, форм, расчёта и кабинета |
| Мобильная навигация без обработчиков | Открытие, закрытие по ссылке, Escape и клику снаружи; aria-expanded |
| Демо-форма без сохранения | Валидация, POST API, база, квитанция, статусы отправки/ошибки |
| `novalidate` при отсутствии JS-валидации | Нативная браузерная и независимая серверная валидация |
| Внешняя загрузка Google Fonts | Локальные шрифты с лицензиями; работа без внешних запросов |
| CSS в нескольких длинных строках | Читаемое форматирование; дополнительные стили в `app.css` |
| Нет проектной структуры | Стандартный Maven layout с разделением предметных областей |
| Нет способа проверить приложение | Java-тесты, браузерный сценарий, CI и фактический отчёт |
| Задержка записи H2 могла терять последний commit при немедленном завершении процесса | `WRITE_DELAY=0` и отдельный автоматический тест перезапуска файловой базы |

## Создано и изменено

Исходные файлы перенесены в `src/main/resources/static/`; оба изменены. `index.html` дополнен калькулятором, рабочим брифом, ссылкой на кабинет и корректным описанием сохранения данных. `styles.css` отформатирован без отказа от исходной визуальной концепции.

Созданы:

- `pom.xml`, `mvnw`, `mvnw.cmd`, `.mvn/wrapper/maven-wrapper.properties`.
- `FormaApplication`; каталог `ServiceCode`, `CatalogService`.
- Заявки: `Inquiry`, `InquiryStatus`, `InquiryRepository`, `InquiryService`, `InquiryConflictException`.
- HTTP-слой: `ApiModels`, `PublicController`, `AdminController`, `ApiExceptionHandler`.
- Защита: `SecurityConfig`, `AbuseProtectionFilter`.
- `application.yml`, SQL-миграция и отдельная тестовая конфигурация.
- Frontend: `api.js`, `script.js`, `app.css`, `login.html/js`, `studio.html/js`, `privacy.html`, `favicon.svg`, локальные шрифты и лицензии.
- Java-тесты в `src/test/java`, `tests/browser.cjs`, `tests/persistence.cjs`, `package.json` и lock-файл.
- `README.md`, документация в `docs/`, скриншоты, CI, Docker/Compose, `.gitignore`, `.gitattributes`, `.dockerignore`, `.env.example`.

Проект опубликован в [Copiturate/forma](https://github.com/Copiturate/forma). Лицензию на исходный код выбирает автор. Ни аккаунты, ни внешние сервисы для локального запуска не требуются.

## Что рассказать на собеседовании

1. **Как превратил статический концепт в продуктовый сценарий.** Сохранил дизайн, добавил расчёт → бриф → обработку командой; интерфейс честно объясняет границы демо.
2. **Почему модульный монолит.** Один JAR и общий origin снижают стоимость запуска и эксплуатации. Микросервисы и SPA не дают пользы этому масштабу.
3. **Как устроена целостность данных.** Сервер считает цену, хранит снимок тарифа, миграции версионируют схему, DTO отделены от сущности.
4. **Как решены повторы и гонки.** UUID + ограничение базы, чтение после отката конкурентной вставки, `@Version` и явная ожидаемая версия при обновлении.
5. **Почему безопасность связана с реальным потоком.** Cookie-сессия + CSRF, нет дефолтного пароля, роли, CSP, ограничение тела, вывод клиентского текста без HTML-интерпретации.
6. **Что именно проверено.** Показать тест конкурентного создания, конфликт версий и полный браузерный сценарий, а затем назвать непроверенные среды из отчёта.
7. **Как развивать проект при росте.** PostgreSQL, несколько сотрудников, история действий, удаление данных по сроку, внешняя отправка уведомлений с outbox. Добавлять по требованиям, а не ради списка технологий.
